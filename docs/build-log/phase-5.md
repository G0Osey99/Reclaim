## Environment constraints that shaped the phase (Part 2.3 traps 1 & 4)

Two Part-5 manual blockers are **not** satisfied on this machine, so — per the
build-guide fallbacks — Phase 5 built and verified everything it can and
documented the rest with exact commands rather than blocking:

1. **No full Xcode (Command Line Tools only).** `xcodebuild` is unavailable, and
   **both XCTest and Swift Testing fail to compile under CLT** (they ship with
   Xcode). So the `xcodebuild test` gate cannot run here. Substitutes (all
   green): an **assertion-runner executable** `ReclaimSelfTest`
   (`scripts/swift-test.sh` → `swift run`) for the view-model unit tests, and a
   headless **`Reclaim --smoke <session>`** mode for the app↔FFI↔golden-image
   integration. Ready-to-run XCTest/XCUITest sources for Phase 6's full-Xcode
   `xcodebuild test` are in `apps/Reclaim/XcodeTests/` (kept out of the SwiftPM
   package so they don't break `swift build`). The universal `.app` is assembled
   by `scripts/build-app.sh` from per-`--triple` SwiftPM builds + `lipo` (the
   `swift build --arch … --arch …` path needs XCBuild from full Xcode).
2. **No paid Developer ID (by choice) — free Apple Development signing instead.**
   Xcode was installed mid-phase and a **free "Apple Development" personal-team
   certificate** (team `FLQ56Q8G95`) added. `scripts/build-app.sh` auto-detects
   it and signs in **`appledev`** mode: hardened runtime, no sandbox, team ID
   baked into the bundle. A research+adversarial-verify workflow confirmed (Apple
   docs + DTS forum threads) that a free Apple Development cert **is sufficient to
   register and run the `SMAppService` privileged daemon on the signing Mac** —
   the paid $99 Developer Program is required only to **notarize for distribution
   to other Macs**. The critical trap it surfaced: **ad-hoc / "Sign to Run
   Locally" is NOT accepted by SMAppService** (it can't securely identify the
   code), so the free real cert — not ad-hoc — is what makes the helper
   installable. Notarization (Developer ID) stays a Phase-6 / ship item. See
   **Signing status** below.

   One-time gotcha on this fresh Xcode: the login keychain had only the expired
   (Feb 2023) original WWDR intermediate, so `codesign` failed with "unable to
   build chain to self-signed root" until the **Apple WWDR CA G3** intermediate
   (`https://www.apple.com/certificateauthority/AppleWWDRCAG3.cer`) was imported.

## Done

### A. `reclaim-ffi` (UniFFI) + `reclaim-preview`
- **`crates/reclaim-preview`** — pure-Rust preview/thumbnail generation from raw
  bytes, no disk writes: JPEG/PNG/GIF/BMP/WebP thumbnails + full-PNG via the
  `image` crate (bounded decoder, 256 MiB alloc cap, graceful `Err` on corrupt
  carved bytes — NFR-6); UTF-8 text and hex-dump previews. HEIC/RAW previews
  decode the file's **embedded JPEG** (the validators' `thumb_offset`/`thumb_len`);
  full HEIC is left to Swift ImageIO.
- **`crates/reclaim-ffi`** — the doc 08 §5 surface via `uniffi::setup_scaffolding!`
  + `#[uniffi::export]` (proc-macro mode): `version`, `list_sources`, `probe`,
  `open_session`, `start_scan` (+ `EventSink` callback) / `pause` / `resume_scan`
  / `stop` / `wait`, `query` (paged from SQLite) / `count_matching` /
  `family_counts` / `get`, `preview`, `extract_temp`, `check_destination`,
  `recover`, `report`, `volumes`, `snapshots` / `snapshot_diff`, `start_image` +
  `ImageJob`. Scans/imaging run on a Rust thread and stream `RcEvent`s to the
  Swift sink; browsing opens its own SQLite read connection (WAL) so results
  page **while a scan is still writing**. The three CLI-only pieces the API map
  flagged (source-string resolution, same-disk + free-space checks, preview
  extraction) are **lifted** against library crates only. Swift bindings are
  generated by an in-crate `uniffi-bindgen` bin in library mode.
- **`reclaim-block::RawDevice::from_fd`** — adopts an fd handed over by the helper
  (`dup(2)`'d); the FFI resolves a `fd:<n>:<bsd>` source spec through it, so the
  GUI reads raw devices via the helper's descriptor **without ever being root**
  (doc 03 §7 "the fd is passed to the core in-process").
- **`reclaim-session::recover`** — the allow-listed home for "recovered files"
  (Part 3.2): extent copy with collision policy, **verify-after-copy** (re-read +
  hash — net-new, FR-RES-4), a JSON manifest, and the temp-extraction helper for
  Swift-side PDF/AVFoundation previews (writes only inside the session dir).
- **`reclaim-session::store`** — additive `offset` paging + `count_matching` /
  `family_counts` for the GUI filter rail. The CLI contract and on-disk session
  format are unchanged (the CLI never sets `offset`).

### B. `Reclaim.app` (SwiftPM package under `apps/Reclaim/`, macOS 13+, SwiftUI)
One SwiftPM package with targets `ReclaimHelperProtocol` (shared XPC protocol),
`ReclaimFFI` (C shim over the generated header), `ReclaimCore` (generated
bindings + a `ReclaimCore` library product), `ReclaimKit` (view models / logic),
`Reclaim` (the app), `ReclaimHelper` (the daemon), and `ReclaimSelfTest`.
- **Screens (doc 08 §2):** onboarding (helper install via `SMAppService.daemon`,
  FDA probe by attempting a boot-store raw read through the helper, deep link to
  the Privacy pane, re-check on focus, "stop using the drive" card); sidebar
  (sources tree / tools / recent sessions); source detail (header, partition
  bar coloured by FS, health chip, warnings, **Image-first** swap when health is
  red, scan-plan disclosure); scan/results **single screen** with live progress
  per pass, rate/ETA, found + read-error counters, "auto-saved Ns ago",
  pause/resume/stop; left filter rail (family+counts, recoverability, engine,
  deleted-only, valid-only, path search, sort); center **grid / list / tree**
  (lazy off-main thumbnail decode with placeholders); right inspector
  (image/text/hex preview, metadata, extents + validity, "open with default app"
  via temp extraction); recover sheet (destination picker, live same-disk
  refusal + space check, collision policy, verify, per-file progress, Open in
  Finder / reveal manifest); image tool with a live bad-sector strip; lost
  volumes adopt; snapshot browser (no root); **RAID builder is a disabled menu
  item** (round 2). System appearance, SF Symbols, native controls, no custom
  chrome. Keyboard: ⌘F filter, Space preview, ⌘R recover, ⌘. stop; every
  thumbnail carries an accessibility label.
- **States table (doc 08 §3):** helper-missing / FDA-missing gate onboarding and
  leave imaging + snapshot browser usable; source-unplugged mid-scan → the
  carve checkpoints and the session is resumable (pause == checkpoint-stop,
  resume == `resume_scan`); a core engine error arrives as a non-fatal
  `Warning` event (toast), other passes continue.
- **Privileged helper (doc 03 §7):** an `NSXPCListener` daemon exposing only
  `openDeviceReadOnly(bsd) -> FileHandle`, `smart(bsd)` (via `diskutil`), and
  `unlockAPFS(volume, passphrase)` (via `diskutil … -stdinpassphrase`). It opens
  fds and shells out to `diskutil` — it **never parses on-disk data**. Both sides
  pin `setCodeSigningRequirement` when `RECLAIM_TEAM_ID` is set (see gaps for the
  ad-hoc case). The fd is handed to the in-process core via `RawDevice::from_fd`.

### C. Signing / packaging (`scripts/build-app.sh`, Part 2.3 trap 4)
Builds a universal `reclaim-ffi` static lib (arm64 + x86_64, `lipo`), regenerates
the bindings, builds `Reclaim` + `ReclaimHelper` per `--triple` and `lipo`s them,
and assembles `dist/Reclaim.app` with the embedded helper, the
`Contents/Library/LaunchDaemons/com.reclaim.helper.plist` (`BundleProgram`),
`Info.plist`, and the hardened-runtime **no-sandbox** entitlements. With a
Developer ID cert + `DEVELOPMENT_TEAM` it Developer ID-signs, builds a DMG,
`notarytool submit --wait`, and staples; otherwise it ad-hoc signs and prints the
exact Phase-6 commands. Sparkle is deferred to Phase 6 (needs the appcast hosting
decision).

### D. Tests
- **Rust FFI round-trip** (`crates/reclaim-ffi/tests/roundtrip.rs`, in `cargo

  browse the same session from a second handle, preview a PNG thumbnail (and

## Decisions made
- **UniFFI 0.29.5, proc-macro + library-mode bindgen.** The latest is 0.32.1;
  0.29 was chosen for a well-understood proc-macro surface. UniFFI is MPL-2.0,
  already on the `deny.toml` allow-list; its transitive tree is all
  MIT/Apache/BSD — `cargo deny` stays green.
- **`image` with only `jpeg,png,gif,bmp,webp`** (pure-Rust codecs, no C image
  libs) so no dylib is added; licenses stay in-list.
- **The FFI orchestrates the core directly rather than the CLI.** The scan
  pipeline (quick → deep → structure → merge), recover and preview live in the
  library crates (`reclaim-session`), which both the CLI and the FFI call. The
  FFI crate itself contains **no write pattern** (`check-readonly` clean); all
  recovery/extraction writes are in `reclaim-session` (already allow-listed).
- **`RawDevice::from_fd` + a `fd:<n>:<bsd>` source spec** make the doc 03 §7
  helper-fd path real and testable (a unit test reads through an fd), not stubbed.
- **One SwiftPM package** (`apps/Reclaim/`) with a `ReclaimCore` library product,
  not two packages — far simpler static-lib linking under CLT. A standalone
  `ReclaimCore` package split is a trivial Phase-6 refactor.
- **Pause == checkpoint-stop; resume == `resume_scan`.** `run_carve` has a single
  cancel hook, not a pause latch; pausing cancels (the carve checkpoints, the
  session stays resumable) and resume re-runs with `resume = true`. This reuses
  the existing resumable model exactly (doc 08 §3 auto-pause).
- **Ad-hoc signing fallback** (Part 2.3 trap 4) — see Signing status.

## Signing status
Now built with the **free Apple Development** cert (team `FLQ56Q8G95`), hardened
runtime, no sandbox — `codesign` chain is Apple Development → WWDR → Apple Root
CA, `flags=0x10000(runtime)`, "satisfies its Designated Requirement", both
Mach-O binaries `x86_64 arm64`, and `ReclaimTeamID` is baked into `Info.plist`
so the app↔helper code requirement is pinned at runtime. This build runs on this
Mac and **can register the SMAppService helper** (`scripts/build-app.sh`,
`appledev` mode). It is **not notarized** (free certs can't be), so Gatekeeper
warns on *other* Macs — irrelevant until distribution.

Local install / run (no paid account needed):

```sh
rm -rf /Applications/Reclaim.app && cp -R dist/Reclaim.app /Applications/
open /Applications/Reclaim.app     # Install helper → approve in Login Items → grant FDA → scan
```

### Exact Phase-6 notarization commands (paid Developer ID, for distribution only)
Once an Apple Developer Program membership + Developer ID Application cert exist
(Part 5.3), `export DEVELOPMENT_TEAM=<TEAMID>` and re-run `scripts/build-app.sh`
(it auto-selects `devid` mode: Developer ID sign + DMG + notarize + staple), or
run:

```sh
export DEVELOPMENT_TEAM=<TEAMID>
xcrun notarytool store-credentials reclaim-notary \
    --apple-id <APPLE_ID> --team-id <TEAMID> --password <APP_SPECIFIC_PW>

codesign --force --timestamp --options runtime \
    --sign "Developer ID Application: <NAME> (<TEAMID>)" \
    --entitlements apps/Reclaim/packaging/Reclaim.entitlements \
    dist/Reclaim.app/Contents/MacOS/ReclaimHelper
codesign --force --timestamp --options runtime \
    --sign "Developer ID Application: <NAME> (<TEAMID>)" \
    --entitlements apps/Reclaim/packaging/Reclaim.entitlements dist/Reclaim.app
codesign --verify --deep --strict --verbose=2 dist/Reclaim.app

hdiutil create -volname Reclaim -srcfolder dist/Reclaim.app -ov -format UDZO \
    dist/Reclaim-0.5.0-beta.dmg
xcrun notarytool submit dist/Reclaim-0.5.0-beta.dmg \
    --keychain-profile reclaim-notary --wait
xcrun stapler staple dist/Reclaim-0.5.0-beta.dmg
xcrun stapler staple dist/Reclaim.app
```

For a stable `SMAppService` daemon registration the helper (and app) must carry
the **same** Developer ID team; set `RECLAIM_TEAM_ID=<TEAMID>` at build time so
both sides pin `setCodeSigningRequirement` (doc 03 §7 "both ways").

## Known gaps (deferred, with phase)
- **`setCodeSigningRequirement` is only pinned when `RECLAIM_TEAM_ID` is set.**
  Ad-hoc builds have no team to pin, so the both-ways check is a no-op in dev;
  it becomes enforcing with a Developer ID team (Phase 6).
- **RAID builder** — disabled menu item only (round 2, doc 08 §2.7).
- **Live bad-sector strip is approximated** from the imager's cumulative
  `done/total/bad` counters (the FFI does not yet stream a per-region map); a
  true per-block strip needs the imager to emit its bad-block ranges (Phase 6).
- **Sparkle auto-update** — deferred to Phase 6 (needs the appcast hosting
  decision + the EdDSA key from Part 5.3).
- **Full HEIC/RAW decode** is Swift-side (ImageIO) from the embedded JPEG /
  temp extraction; the Rust preview only decodes the embedded JPEG.
