# 11 — Safety, Legal & Licensing

## 1. Data-safety guarantees (product promises)

1. **Read-only sources.** No code path can write to a scanned device. Enforced statically and dynamically (doc 09 §5). Filesystem *repair* (rewriting boot sectors etc., TestDisk-style) is a separate future mode, behind a separate binary/flag, with mandatory pre-image and explicit confirmation naming the device.
2. **Never recover onto the source.** Whole-disk identity comparison; override flag is deliberately long and ugly.
3. **Image-first on unhealthy media.** UI forces the flow; CLI warns.
4. **Session durability.** Crash or unplug loses at most one checkpoint interval.
5. **Honesty about chances.** TRIM'd SSDs, overwritten extents and encrypted volumes are labelled; no "100 % recovery" marketing.
6. **No telemetry in the core; opt-in crash reports in the GUI, never containing user data or file names.**

## 2. Licensing of dependencies — avoid contamination

Reclaim is intended to ship under **Apache-2.0 (or MIT/Apache dual)** so commercial options stay open. That imposes rules:

| Project | License | Can we… |
|---------|---------|---------|
| PhotoRec / TestDisk | GPLv2+ | **Read** for understanding; **must not copy code** or signature tables verbatim. Rewrite signatures from primary format specs (they are facts, but PhotoRec's specific validator logic is code). Running PhotoRec in CI for benchmarks is fine. |
| The Sleuth Kit | IBM Public License / CPL (+ Apache for some) | Don't link; clean-room from specs. |
| libfsapfs / libewf / libyal (Joachim Metz) | LGPLv3+ | Dynamic linking possible but awkward on macOS for a notarized app; prefer own implementations. Documentation (the `*.asciidoc` format docs) is under GFDL/CC — read for knowledge, cite. |
| apfs-fuse | GPLv2 | Read only. |
| dislocker (BitLocker) | GPLv2 | Read only; implement from Microsoft's published BitLocker spec + libbde docs. |
| ffmpeg | LGPL (GPL with some options) | If used for previews, dynamic-link the LGPL build and keep it optional; or use AVFoundation on macOS (no license issue). |
| libheif / libde265 | LGPL / (x265 is GPL — avoid) | Dynamic link LGPL; on macOS prefer ImageIO for HEIC decode. |
| Rust crates | mostly MIT/Apache | Run `cargo deny` with an allow-list; block GPL/AGPL/LGPL-static. |
| Apple File System Reference | Apple doc, © Apple | Implementation from spec is fine; don't redistribute the PDF. |

Keep a `THIRD_PARTY.md` generated by `cargo about`.

## 3. Trademarks & comparisons
Naming competitors in comparison tables is fine (nominative use). Don't use their logos or imply endorsement. Publish benchmark methodology (doc 09) alongside any comparative claims.

## 4. Forensic soundness (secondary market)
- Deterministic result IDs, full audit log (`log.ndjson` with hashes of source header/footer), optional E01/AFF4 output, SHA-256/BLAKE3 for every recovered file in `manifest.json`.
- Document that Reclaim is not a certified forensic tool (no NIST CFTT testing) unless you pursue it.

## 5. Legal considerations for users
- Recovering data from media you do not own or are not authorized to access may be illegal; the license/EULA and first-run text should say so plainly.
- Encrypted volume unlock features only accept credentials the user supplies; Reclaim never attempts brute force.
- Export controls: implementing AES for BitLocker/LUKS/FileVault decryption triggers standard open-source crypto export notification considerations if distributed from the US (the usual ECCN 5D002 / open-source exemption notice). Check current rules when M7 ships.

## 6. Privacy
- Recovered content, thumbnails and session DBs may contain sensitive user data → sessions default to `~/Library/Application Support/Reclaim/sessions` with `0700` permissions; "Delete session" wipes thumbnails.
- No cloud features.

## 7. Distribution & support
- Direct + Homebrew; no Mac App Store (sandbox incompatible).
- If commercial (open-core): the core & CLI stay Apache-2.0; GUI, RAID, and video reassembly may be proprietary or source-available; document the line in `LICENSE-COMMERCIAL.md` from day one so contributors know.
- Contributor License Agreement or DCO sign-off for external signature contributions.
